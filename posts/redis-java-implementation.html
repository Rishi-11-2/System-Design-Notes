Implementing Redis from Scratch in Java — NIO Event Loop, RESP Parser & Ping Server

📁 Category: In-Memory & Redis
← Back to All Notes
📌 Hands-On Engineering Walkthrough

To truly understand Redis internals, We built a lightweight, fully functional in-memory Redis server from scratch in Java. This guide walks through the actual implementation code located in the Redis_Implementation/ directory of this repository: designing the RESP protocol decoder, handling arbitrary bulk strings and arrays, building the Java NIO Selector non-blocking event loop, and responding to PING / PONG commands via standard redis-cli.

1. High-Level Architecture

Our custom Java Redis server adheres to the core principles of Redis:

  1. Single-Threaded Reactor Pattern: A single Java thread runs an event loop polling a java.nio.channels.Selector.
  2. Non-Blocking Sockets: ServerSocketChannel and incoming client SocketChannels are configured with configureBlocking(false).
  3. Binary-Safe Wire Protocol: Incoming byte buffers are parsed using a custom stateful RESP decoder.
  4. Direct CLI Compatibility: You can connect using the official C redis-cli binary or any standard Redis client (Jedis, Lettuce, redis-py)!

2. Implementing the RESP Protocol (RESP.java)

Let's inspect how the RESP wire protocol is decoded. In Redis_Implementation/RESP.java, we parse input streams according to RESP prefixes:

Java: RESP.java (Decoder Core)
public class RESP {
    public static Object decode(byte[] buffer) {
        if (buffer == null || buffer.length == 0) return null;
        char prefix = (char) buffer[0];

        switch (prefix) {
            case '+': // Simple String
                return parseSimpleString(buffer);
            case '-': // Error
                return parseError(buffer);
            case ':': // Integer
                return parseInteger(buffer);
            case '$': // Bulk String
                return parseBulkString(buffer);
            case '*': // Array
                return parseArray(buffer);
            default:
                throw new IllegalArgumentException("Unknown RESP prefix: " + prefix);
        }
    }
}

Parsing Bulk Strings ($) and Arrays (*)

When clients send commands like *1 $4 PING , the decoder reads the array count, followed by each bulk string's length indicator:

Java: Bulk String & Array Parsing
private static String parseBulkString(byte[] buffer) {
    // Reads length after '$', finds CRLF, extracts exact bytes
    int crlfIndex = findCRLF(buffer, 0);
    int length = Integer.parseInt(new String(buffer, 1, crlfIndex - 1, StandardCharsets.UTF_8));
    if (length == -1) return null; // Null Bulk String

    int contentStart = crlfIndex + 2;
    return new String(buffer, contentStart, length, StandardCharsets.UTF_8);
}

private static Object[] parseArray(byte[] buffer) {
    // Reads element count after '*', iteratively parses nested elements
    int crlfIndex = findCRLF(buffer, 0);
    int count = Integer.parseInt(new String(buffer, 1, crlfIndex - 1, StandardCharsets.UTF_8));
    Object[] elements = new Object[count];
    // ... extracts each child element and advances buffer cursor
    return elements;
}

3. Building the Java NIO Selector Event Loop (RedisEventLoopServer.java)

The core of our server is the single-threaded event loop implemented in Redis_Implementation/RedisEventLoopServer.java:

Java: Non-Blocking Event Loop with Selector
public class RedisEventLoopServer {
    private final int port;
    private Selector selector;
    private ServerSocketChannel serverChannel;

    public void start() throws IOException {
        selector = Selector.open();
        serverChannel = ServerSocketChannel.open();
        serverChannel.bind(new InetSocketAddress(port));
        serverChannel.configureBlocking(false);

        // Register Server Socket for incoming connection acceptance
        serverChannel.register(selector, SelectionKey.OP_ACCEPT);
        System.out.println("Redis Event Loop Server listening on port " + port);

        // Infinite Single-Threaded Reactor Event Loop
        while (true) {
            selector.select(); // Blocks until at least one channel is ready
            Set<SelectionKey> keys = selector.selectedKeys();
            Iterator<SelectionKey> iterator = keys.iterator();

            while (iterator.hasNext()) {
                SelectionKey key = iterator.next();
                iterator.remove();

                if (key.isAcceptable()) {
                    handleAccept(key);
                } else if (key.isReadable()) {
                    handleRead(key);
                }
            }
        }
    }
}

4. Connection Handling and Command Execution

When a client initiates a connection, handleAccept creates a non-blocking SocketChannel. When bytes arrive, handleRead buffers them, invokes our RESP decoder, and dispatches the command:

Java: Command Dispatcher & Response
private void handleRead(SelectionKey key) throws IOException {
    SocketChannel client = (SocketChannel) key.channel();
    ByteBuffer buffer = ByteBuffer.allocate(1024);
    int bytesRead = client.read(buffer);

    if (bytesRead == -1) { // Client disconnected
        client.close();
        return;
    }

    buffer.flip();
    byte[] data = new byte[buffer.remaining()];
    buffer.get(data);

    // Decode RESP Command Array (e.g. ["PING"] or ["PING", "Hello"])
    Object decoded = RESP.decode(data);
    if (decoded instanceof Object[]) {
        Object[] commandArgs = (Object[]) decoded;
        String command = commandArgs[0].toString().toUpperCase();

        if ("PING".equals(command)) {
            if (commandArgs.length == 1) {
                // Default PING -> returns Simple String "+PONG\r\n"
                client.write(ByteBuffer.wrap("+PONG\r\n".getBytes(StandardCharsets.UTF_8)));
            } else {
                // PING with message -> returns Bulk String "$<len>\r\n<msg>\r\n"
                String msg = commandArgs[1].toString();
                String response = "$" + msg.length() + "\r\n" + msg + "\r\n";
                client.write(ByteBuffer.wrap(response.getBytes(StandardCharsets.UTF_8)));
            }
        }
    }
}

PONG
127.0.0.1:6379> PING "Hello from Java Redis!"
"Hello from Java Redis!"

6. Key Takeaways from the Implementation

  • Single-Thread Simplicity: Because all commands execute synchronously on the single reactor thread, there is no need for synchronized blocks or concurrent maps.
  • Zero-Copy Buffers: Proper management of ByteBuffer.flip(), compact(), and capacity allocation is essential for handling partial TCP frame deliveries without buffer leaks.
  • RESP Versatility: The simplicity of the RESP wire protocol makes writing custom high-performance parsers straightforward.
