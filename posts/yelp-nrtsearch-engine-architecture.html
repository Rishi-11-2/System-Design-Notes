Yelp nrtSearch: Disaggregated Near-Real-Time Lucene Search Architecture

Providing millions of local business search results with sub-second attribute freshness requires rethinking traditional full-text search clusters. Discover how Yelp engineered nrtSearch—an open-source search platform decoupling index-writing primaries from stateless search replicas via segment-level streaming over gRPC, slashing CPU usage by 60% and delivering true near-real-time visibility.

1. The Near-Real-Time Search Dilemma

At Yelp, search is the primary interface for over 100 million consumers discovering restaurants, home services, and local businesses. However, business attributes are highly dynamic:

  • Instant Operational Status: A restaurant marking itself "Temporarily Closed" due to emergency maintenance must vanish from open listings within seconds.
  • Live Table Availability: Reservation slots and waitlist times fluctuate every second as patrons arrive and depart.
  • Continuous Content Streams: Thousands of reviews, star ratings, and uploaded food photos stream into the platform continuously.

Achieving sub-second indexing freshness while concurrently servicing thousands of complex, geo-spatial, multi-facet search queries per second (QPS) with sub-30ms p99 latency breaks conventional clustered search engines.

2. Where Elasticsearch Hit the Wall

Yelp historically operated massive Elasticsearch clusters. However, at scale, Elasticsearch's core architectural model revealed three fundamental bottlenecks:

  1. Duplicate Document Indexing ($N \times$ CPU Waste): In Elasticsearch, every replica node independently ingests raw JSON documents, executing duplicate tokenization, stemming, analyzer parsing, and segment creation. If a shard has 1 primary and 4 replicas, CPU work is multiplied by 5x!
  2. Cluster State Overhead: Frequent index updates, mapping changes, and shard health gossiping saturated the cluster master nodes, causing cluster state lock freezes during traffic spikes.
  3. I/O & Segment Merge Contention: Search read queries competed directly with heavy background Lucene segment compaction on the same physical instances, triggering tail-latency spikes ($p_{99} > 800\text{ms}$).

3. nrtSearch Disaggregated Architecture

To eliminate redundant indexing and isolate search compute from indexing compute, Yelp engineered nrtSearch—a high-throughput, standalone gRPC search engine built on modern Apache Lucene:

4. Primary-Replica Segment Streaming over gRPC

The core innovation of nrtSearch is Segment-Level Physical Replication:

  • Single Ingestion Pipeline: Only the Primary node ingests documents. It performs all intensive text tokenization, phonetics, and inverted list compression.
  • Direct Segment Streaming: When the Primary flushes a new segment (e.g., every 500ms), it notifies all search replicas via gRPC. Replicas pull only the newly created segment delta files.
  • Instantaneous Visibility: Replicas call IndexReader.openIfChanged() over memory-mapped segment files. The new documents become searchable across all replicas within under 1 second with virtually zero replica CPU expenditure.

5. Stateless Search & S3 Archival Storage

By separating persistence from query execution, nrtSearch achieves true stateless search scalability:

The Primary node asynchronously backs up every flushed Lucene segment to Amazon S3:

  • Elastic Horizontal Autoscaling: During lunchtime and evening traffic surges, Yelp spins up hundreds of ephemeral replica nodes in Kubernetes.
  • Fast Bootstrap: New replicas pull the latest segment snapshot directly from S3 or peer replicas, warming local NVMe page caches and joining the active gRPC load balancer pool in under 60 seconds.
  • Disaster Recovery: If the Primary node suffers a hardware crash, a new Primary is elected, restores state from S3, catches up on the Kafka replication queue, and resumes indexing within seconds.

6. High-Throughput gRPC Query Execution

nrtSearch replaces HTTP/JSON REST APIs with low-latency binary gRPC over HTTP/2:

  • Protobuf Serialization: Protobuf binary payloads reduce network bandwidth by 40% and eliminate JSON parsing CPU overhead on frontend gateways.
  • Pluggable Dynamic Rescoring: Supports custom C++ and Java scoring plugins directly in the Lucene collector loop, combining BM25 relevance with machine learning ranking models (user preferences, distance decay, and pricing tier).

8. Key Architectural Takeaways

  • Replicate Segments, Not Documents: Replicating pre-built Lucene binary segments eliminates redundant parsing and indexing across replicas, saving up to 60% of total cluster compute.
  • Isolate Ingestion from Search Workloads: Dedicating a single Primary to indexing and decoupling read replicas guarantees that heavy segment merging never causes query tail-latency spikes.
  • Disaggregate Persistence to Cloud Storage: Backing Lucene segments to object storage (S3) transforms search nodes into stateless workers, enabling rapid elastic autoscaling and trivial disaster recovery.
  • Binary Protocols Beat JSON REST at Scale: Replacing JSON REST interfaces with binary gRPC streaming eliminates serialization overhead and supports high-throughput connection multiplexing.
