Pinterest Goku TSDB Architecture: In-Memory Time Series Storage & Gorilla Compression at Scale

Monitoring billions of real-time metrics across thousands of microservices with sub-50ms dashboard query latencies breaks conventional disk-backed databases. Discover how Pinterest engineered Goku—a high-performance C++ in-memory time series database implementing Gorilla compression algorithms, inverted tag indexes, and tiered S3 archival to replace OpenTSDB and slash hardware costs by 75%.

1. Telemetry Scale & OpenTSDB Limits

Pinterest operates hundreds of millions of user boards, serving visual recommendations to over 450 million active pinners. Supporting this requires monitoring millions of time-series metrics per minute:

  • Scale: Ingesting over billions of metric data points per day across thousands of server hosts and application services.
  • SLA Requirements: Alerting engines and real-time operational dashboards require sub-50ms query response times over 12-hour windows.
  • The Failure of OpenTSDB: Pinterest previously relied on OpenTSDB backed by Apache HBase on HDFS. At scale, HBase suffered from severe JVM garbage collection freezes, heavy write amplification during compaction, and query aggregation latencies exceeding 5 to 10 seconds.

2. Gorilla Compression Algorithms: 12x Memory Reduction

To make storing billions of telemetry points entirely in RAM economically feasible, Goku implements the Facebook Gorilla Compression Algorithms:

1. Timestamp Delta-of-Delta Compression

Metrics typically arrive at regular intervals (e.g., every 10 seconds). The delta between consecutive timestamps $D = T_i - T_{i-1}$ is nearly constant. By computing the delta-of-delta $D' = D_i - D_{i-1}$:

  • If $D' = 0$, store a single bit '0'!
  • If $-63 \le D' \le 64$, store '10' followed by 7 bits.
  • Compacts standard 8-byte (64-bit) Unix timestamps down to an average of 1.37 bits per timestamp!

2. Floating-Point Value XOR Compression

Consecutive metric values (e.g. CPU% or memory usage) are often identical or change only in lower-order bits:

  • Compute bitwise XOR of current float with previous float: $X = V_i \oplus V_{i-1}$.
  • If $X = 0$, store a single bit '0'.
  • If $X \neq 0$, store variable-length bit-packed bits excluding redundant leading and trailing zeros.
  • Compacts 8-byte double precision floats down to an average of 1.3 bytes per value (83% compression).

4. Tag Inverted Indexes & Roaring Bitmaps

In modern telemetry, metrics are queried by multidimensional tags: service=api AND host=ip-10-0-1-5 AND region=us-east-1.

  • Series ID Mapping: Every unique combination of metric name and tags is assigned a dense 32-bit integer SeriesID.
  • Inverted Index with Roaring Bitmaps: Each tag key-value pair points to a Roaring Bitmap containing the SeriesIDs matching that tag.
  • Bitwise AND Filtering: Querying multi-tag filters is reduced to sub-millisecond bitwise AND operations across bitmaps, retrieving thousands of matching time-series in under 1ms.

5. Sub-50ms Query Vector Execution

Goku's query engine is optimized for high-speed columnar data scans:

  • SIMD Vectorization: Scanning and aggregating floating-point time slices (e.g. computing the 95th percentile CPU across 1,000 servers) utilizes AVX-512 vector instructions.
  • Lock-Free Reader Concurrency: Time series segments are appended by a single ingestion worker and read lock-free via atomic length pointers, eliminating mutex contention.

6. Storage Tiering & Long-Term S3 Archival

Telemetry value degrades exponentially over time. Pinterest implements a two-tiered persistence model:

  • Hot In-Memory Tier (0 to 24 Hours): Retains 1-second and 10-second high-resolution data in RAM for interactive real-time debugging and alerting. Sub-50ms latency.
  • Cold S3 Tier (24 Hours to 1 Year): As segments age past 24 hours, background worker threads downsample data (roll up 10s intervals into 5-minute averages), pack compressed blocks, and upload them to Amazon S3.

8. Key Architectural Takeaways

  • In-Memory TSDBs Beat Disk Engines for Dashboards: Serving live operational telemetry from RAM eliminates disk seek bottlenecks and delivers deterministic sub-50ms queries.
  • Gorilla Compression Makes RAM Affordable: Delta-of-delta timestamp encoding and floating-point XOR packing compress time-series data by over 12x, fitting billions of points into modest RAM pools.
  • Bitmaps Accelerate Multi-Dimensional Tag Queries: Roaring Bitmaps transform complex metadata filtering into ultra-fast CPU bitwise operations.
  • Tier Storage by Data Age: Keep raw high-resolution metrics in memory for 24 hours, downsample older data, and archive to inexpensive cloud object storage (S3) for historical analytics.
