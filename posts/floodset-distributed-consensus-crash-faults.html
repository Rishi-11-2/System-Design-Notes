FloodSet Algorithm: Distributed Consensus Under Crash Faults & $f+1$ Round Bounds

📁 Category: Distributed Algorithms & Crash Fault Tolerance
📥 Download Technical PDF (3 Pages)
📌 Primary Algorithmic Takeaway: Overcoming Node Crashes via the Clean-Round Principle

In distributed consensus, the Crash-Stop (Fail-Stop) failure model captures scenarios where server nodes can silently die at any arbitrary point in execution, including mid-broadcast while transmitting to a subset of peers. The FloodSet algorithm guarantees unanimous distributed consensus among all non-faulty processes in a synchronous network tolerating up to $f$ arbitrary node crashes. By executing for exactly $f + 1$ rounds, the protocol guarantees via the Pigeonhole Principle that at least one round experiences zero crashes (the "Clean Round"). During this clean round, all surviving processes synchronize their knowledge sets, guaranteeing unanimous decision agreement.

1. The Distributed Consensus Problem Under Crash Failures

In an environment of $n$ distinct processes, each node $p_i$ begins with an initial input value $v_i \in \{0, 1\}$. Nodes must execute an algorithm and irrevocably output a decision value $d_i \in \{0, 1\}$.

A valid distributed consensus protocol must strictly satisfy three properties:

  1. Agreement: All non-faulty processes must decide on the exact same value: $$\forall p_i, p_j \text{ (non-faulty)} \implies d_i = d_j$$
  2. Validity: If all processes begin with the same initial input $v$, every non-faulty process must decide $v$. (This prevents trivial solutions like always deciding 0).
  3. Termination: Every non-faulty process must eventually decide and halt within a finite, bounded number of rounds.

2. Why Exactly $f + 1$ Rounds? The Clean-Round Principle

A fundamental theorem in distributed computing (proven by Fischer and Lynch, 1982) states:

The $f+1$ Round Lower Bound: In a synchronous system of $n$ processes with up to $f$ crash failures ($f \le n - 2$), any deterministic consensus protocol requires at least $f + 1$ rounds in the worst case.

The intuition rests on the Pigeonhole Principle:

  • An adversary has a budget of at most $f$ crash failures.
  • The adversary can deploy these crashes maliciously across rounds. In the worst case, the adversary crashes exactly 1 process per round.
  • In a protocol running for $f + 1$ rounds, there are $f + 1$ rounds but at most $f$ crashes.
  • Therefore, there must exist at least one round in which ZERO processes crash!

This round is called the Clean Round. In this round, every message sent by every surviving node is received by every other surviving node, making their knowledge sets identical.

3. The FloodSet Protocol Specification

The state maintained by each process $p_i$ is a set $W_i \subseteq \{0, 1\}$ representing all input values that process $p_i$ has witnessed.

Step-by-Step Execution

  1. Initialization: $$W_i \gets \{v_i\} \quad \text{where } v_i \in \{0, 1\} \text{ is } p_i\text{'s initial input}$$
  2. Rounds $r = 1, 2, \dots, f + 1$:
    • Process $p_i$ broadcasts its set $W_i$ to all $n$ processes (including itself).
    • Process $p_i$ receives messages $M_j$ from all active, non-crashed processes $p_j$.
    • Process $p_i$ computes the union of all received sets: $$W_i \gets W_i \cup \bigcup_{j \in \text{senders}} M_j$$
  3. Decision at Round $f + 1$:
    • Case 1 ($|W_i| = 1$): If $W_i = \{v\}$, decide $v$. (Process $p_i$ only ever witnessed value $v$ throughout all rounds).
    • Case 2 ($|W_i| = 2$): If $W_i = \{0, 1\}$, decide $0$ (the canonical deterministic fallback value).

4. Formal Mathematical Proof of Correctness

1. Proof of Validity

  • Case $v = 0$ everywhere: If all processes start with $v_i = 0$, every initial set is $W_i = \{0\}$. Since no node ever introduces $1$, the set union $W_i$ remains $\{0\}$ across all $f+1$ rounds. At termination, $|W_i| = 1$, so every non-faulty node decides $0$.
  • Case $v = 1$ everywhere: If all processes start with $v_i = 1$, every initial set is $W_i = \{1\}$. The value $0$ is never injected. At round $f+1$, $W_i = \{1\}$, so every non-faulty node decides $1$.

Validity holds in all executions. $\blacksquare$

2. Proof of Agreement

We prove that at the end of round $f + 1$, all non-faulty processes possess identical sets: $W_i = W_j$.

  1. Since at most $f$ processes crash during the entire execution of $f + 1$ rounds, there exists at least one round $k \in \{1, 2, \dots, f + 1\}$ in which zero processes crash.
  2. In this clean round $k$, every process that was alive at the beginning of round $k$ successfully broadcasts its set to all surviving processes.
  3. Therefore, every process alive at the end of round $k$ computes the exact same union: $$W_{\text{clean}} = \bigcup_{p \text{ alive in round } k} W_p$$
  4. Thus, for all processes $p_i, p_j$ alive at the end of round $k$: $$W_i = W_j = W_{\text{clean}}$$
  5. In subsequent rounds $k+1, \dots, f+1$, every node only broadcasts subsets of $W_{\text{clean}}$. No node can ever learn any value outside $W_{\text{clean}}$.
  6. Therefore, at the end of round $f + 1$, for all non-faulty processes $p_i, p_j$: $$W_i = W_j$$
  7. Because their sets $W$ are identical, they evaluate the exact same decision rule and output the exact same decision value: $d_i = d_j$.

Agreement is mathematically guaranteed. $\blacksquare$

5. Complexity Analysis & Bounds

Time Complexity: Strictly $f + 1$ Rounds

The algorithm terminates in exactly $f + 1$ rounds. Because of the Fischer-Lynch lower bound, no algorithm can guarantee consensus in $f$ rounds under crash failures. FloodSet is strictly time-optimal.

Message Complexity: $\mathcal{O}(n^2 (f + 1))$

In each round, every alive process broadcasts its set to all $n$ processes ($\le n^2$ messages per round). Across $f + 1$ rounds, total messages: $\mathcal{O}((f + 1) n^2)$ messages.

6. Comparison: FloodSet vs. EIG vs. Paxos

Consensus Algorithm Failure Model Network Model Rounds to Terminate Message Content
FloodSet Crash-Stop ($f < n$) Synchronous $f + 1$ rounds Flat sets of values ($W \subseteq \{0, 1\}$)
Exponential Info Gathering (EIG) Crash or Byzantine ($n \ge 3f+1$) Synchronous $f + 1$ rounds Tree of paths ("who told whom what")
Paxos / Raft Crash-Recovery (Quorum $f < n/2$) Asynchronous (Partially Synchronous) Unbounded in worst-case; 1–2 RTTs normally Log entries, terms, ballot numbers

7. Systems Engineering Takeaways

  1. The Price of Crash Tolerance is Latency: You cannot overcome $f$ crash faults in synchronous networks in fewer than $f+1$ rounds. If a system must tolerate 3 server crashes, it must budget for at least 4 communication rounds.
  2. Mid-Broadcast Crashes are the True Adversary: A node crashing before sending anything is harmless. The dangerous failure mode is a node dying halfway through broadcasting—sending to half the cluster and dying before reaching the other half. The $f+1$ round duration ensures the remaining nodes heal this divergence.
  3. Flat Sets Fail Under Byzantine Attacks: FloodSet relies on honest nodes only reporting values they witnessed. If a malicious Byzantine node lies about seeing both $\{0, 1\}$, it can force arbitrary fallback decisions. To handle Byzantine traitors, systems must upgrade from flat sets to EIG Trees.
